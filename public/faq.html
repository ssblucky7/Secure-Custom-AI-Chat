General

About the Project

What is Secure Custom AI Chat? +

Secure Custom AI Chat is a self-hosted, open-source web application that provides a unified chat interface for interacting with AI models from multiple providers. It runs as a Node.js server that proxies all requests to AI providers server-side — meaning your API keys are stored on the server and never exposed to the browser or frontend code.

Is it free? +

Yes. The software itself is free and open-source under the MIT License. There is no subscription, no account, and no usage fee for the software.

You do pay for the AI API usage charged by your chosen provider. For example, OpenAI charges per token. Some providers like Ollama (local) offer free models with no API costs.

How is it different from ChatGPT, Claude web, or OpenRouter? +

Key differences:

  • Self-hosted — Runs on your own server, not a third-party service.
  • Multi-provider — Works with OpenAI, Anthropic, Groq, Ollama, and 9+ other providers in one interface.
  • No account required — Users don't need to register or log in.
  • Local model support — Connect to Ollama or LM Studio for fully private, no-cost AI.
  • Server-side key proxy — API keys stay on your server, not in browser localStorage.
Who is it for? +

It is designed for developers, IT administrators, home lab enthusiasts, and privacy-conscious users who want to use AI models without depending on a third-party chat service. It is also useful for teams that want to share a single AI chat interface without distributing API keys to every user.

Security

Security Questions

How does server-side API key protection work? +

In default mode (ALLOW_USER_PROVIDERS=0), you set your API key as AI_API_KEY in the server's .env file. The key is loaded into the server process at startup and never sent to the browser in any response.

When the browser sends a chat request to POST /api/chat, the server appends your stored key to the request before forwarding it to the AI provider. The browser never sees the key.

What is SSRF protection and why does it matter? +

Server-Side Request Forgery (SSRF) is an attack where a malicious user provides a URL that tricks your server into making requests to internal services (e.g., AWS metadata endpoint, internal databases).

Secure Custom AI Chat blocks SSRF by:

  • Resolving the provider hostname via DNS before making any request.
  • Blocking all private IP ranges: 10.x, 172.16–31.x, 192.168.x, 127.x, 169.254.x, CGNAT (100.64-127.x), and IPv6 equivalents.
  • Blocking known localhost hostnames (localhost, lvh.me, etc.).
  • Blocking URLs with embedded credentials.
Is my conversation data private? +

Conversation history is stored only in your browser's localStorage. Nothing is saved on the server — the server is stateless. Your messages are sent to the AI provider you configure, subject to their privacy policy.

The Secure Custom AI Chat server does not log, store, or retain your conversation content.

Should I add authentication if I deploy it publicly? +

Yes. The application has no built-in login system. If you deploy it on a public URL, anyone who finds the URL can use the API (and potentially exhaust your API credits).

You can protect it by:

  • Adding HTTP Basic Auth via your reverse proxy (nginx, Caddy, etc.).
  • Restricting access by IP using your firewall or reverse proxy.
  • Deploying behind a VPN.
  • Setting ALLOW_USER_PROVIDERS=0 so no API key is needed client-side (reduces risk but does not prevent usage).
Providers & Models

Providers & Models

Which AI providers are supported? +

Any provider using the OpenAI-compatible API or the Anthropic Messages API. Built-in presets include:

  • ZenMux (OpenAI-compatible and Anthropic)
  • OpenAI (GPT-4o, GPT-4.1, etc.)
  • Anthropic (Claude Sonnet, Claude Haiku, etc.)
  • OpenRouter (access to 100+ models)
  • Groq (fast inference)
  • Together AI
  • DeepSeek
  • Mistral AI
  • Ollama (local)
  • LM Studio (local)
Can I use Ollama for fully local, private AI? +

Yes. Set ALLOW_PRIVATE_PROVIDER_URLS=1 in your .env file. Then in the app settings, select the Ollama / local preset, which sets the base URL to http://localhost:11434/v1. All requests are processed on your local machine with no data leaving your network.

How do I load available models from my provider? +

In the settings dialog, after entering your Base URL and API key, click the Load models button. The server calls the provider's /models endpoint and returns the list. You can then select from the loaded models or type any model ID manually.

Usage

Using the App

Does it work offline? +

The app shell (HTML, CSS, JavaScript, and icons) is cached by the service worker and loads offline. Your saved chat history in localStorage is also accessible offline.

However, sending new messages requires an active internet connection to reach the AI provider (or a local Ollama instance on your network).

Can I install it as a mobile app? +

Yes. On iOS, open the app in Safari and tap Share → Add to Home Screen. On Android, tap the browser menu and choose Install app or Add to Home Screen. On desktop Chrome/Edge, click the install icon in the address bar.

Once installed, the app runs in standalone mode (no browser chrome) and appears as a regular app icon on your device.

Where is my chat history stored? +

Conversation history is stored in your browser's localStorage under the key secureCustomAIStateV1. Up to 30 conversations are kept, sorted by most recently updated. Clearing your browser data removes the history.

How do I export a conversation? +

Click the Export button in the top toolbar while viewing a conversation. A Markdown file (.md) will be downloaded to your device containing all messages with role headers (You / Assistant).

Setup

Installation & Setup

How do I install Secure Custom AI Chat? +

Requirements: Node.js 18 or higher.

  1. Download or clone the repository.
  2. Copy .env.example to .env and fill in your settings.
  3. Run npm install to install dependencies.
  4. Run node server.js or npm start to start the server.
  5. Open http://localhost:3000 in your browser.

See the full documentation for production deployment instructions.

What are the system requirements? +

Server: Node.js 18 or higher. Any operating system. Minimal CPU/memory requirements — the server uses native Node.js fetch and does not run AI models locally (unless using Ollama).

Browser: Any modern browser supporting ES2020+. Chrome, Firefox, Safari 14+, Edge. PWA installation requires Chrome, Edge, or Safari.
